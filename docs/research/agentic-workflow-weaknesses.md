# Research: RepoDB weaknesses in agentic workflows

## Summary

RepoDB offers reproducible commit-scoped exact and embedding search, but a coding agent's active task usually spans an uncommitted checkout, the *reason* for a change, and several source origins. The largest gaps are the deliberate exclusion of staged/unstaged/untracked content from the current-worktree scope, limited change-intent retrieval, and surprising interactions among duplicate collapse, commit selection, and imports. Address these with an explicit ephemeral overlay and provenance-aware change retrieval before broadening automatic acquisition; measure answer quality and end-to-end cost rather than assuming that more indexed material or a faster vector query improves an agent's work. **External Git-object availability is an intentional storage dependency, not a weakness assessed here.**

## Evidence and limits

This is a review of the current checkout's source, docs, skills, and selected CLI tests, not a production usage study or a new performance benchmark. `git status --short` showed pre-existing deletions of `.agents/skills/*` and `UNINSTALL.md` and a modified `tests/agent_skills.rs`; these changes were left alone. The repository's `skills/repodb-*` files remain present. Three relevant CLI tests passed locally: `git_import_accepts_one_optional_revision_and_pins_it_to_the_resolved_commit`, `search_scope_filters_repo_and_document_sources_for_all_modes`, and `exact_commit_inclusion_and_exclusion_select_before_all_search_modes`. First-party citations identify files/functions as inspected in this checkout, not a separately pinned revision. Existing research in [`docs/issue-36-source-context-research.md`](../issue-36-source-context-research.md) is explicitly preliminary and its external references were not validated; this document does not promote those links to verified evidence. The benchmark in [`docs/issue-32-benchmark.md`](../issue-32-benchmark.md) is a historical controlled fixture, not a measurement of this working tree or a real embedding model. The researcher's external lookup tools were unavailable, so external claims are omitted rather than cited without verification.

Terminology follows [`GLOSSARY.md`](../../GLOSSARY.md): *indexed unit*, *segmentation kind*, *source reference*, *imported source*, *current worktree scope*, *exact search*, and *embedding search*. [README](../../README.md) describes the public contract; code observations supersede any broad interpretation of that prose. `AGENTS.md` directs agents to refresh when stale and explicitly makes the post-commit hook opt-in; this checkout has `core.hooksPath=hooks`, and [`hooks/post-commit`](../../hooks/post-commit) exists. Hook presence does not guarantee the database is fresh (other refs can change, and hook execution may fail).

## Findings and design options

### P0 — active-worktree freshness is not visible to search

**Verified.** [`src/history.rs::Scope::resolve`](../../src/history.rs) selects the checked-out HEAD only when it is already in the index; [`src/main.rs::execute`](../../src/main.rs) invokes scope resolution and search, not refresh. [`src/history.rs::prepare_refresh` / `refresh_scoped`](../../src/history.rs) read commit trees, while [`README.md`, “Git history and scopes”](../../README.md) explicitly excludes staged, unstaged, and untracked content from `--current-worktree`. `refresh --changed` requires a branch and an indexed first parent and indexes only HEAD; [`hooks/post-commit`](../../hooks/post-commit) is opt-in and can fail under those conditions. `refresh --update COMMIT` captures one commit but not uncommitted content or imports. **Agent impact (inference):** an agent can receive a confident, correctly referenced answer that omits the very edits it is reviewing, and HEAD absent from the snapshot silently gives zero local matches rather than an obvious freshness error. The latter is documented in README, not hidden behavior.

**Proposal.** Add an explicit, transient overlay sourced from a consistent snapshot of index + worktree + untracked eligible files, with distinct `origin`/`state` (`HEAD`, staged, unstaged, untracked), content hashes and snapshot time; precedence should not conflate staged and unstaged versions. Offer `--worktree-overlay` or a separate command, retain HEAD-only as the reproducible default, and expose `index_head`, `live_head`, freshness status, and overlay coverage in JSON. Lightweight immediate mitigation: agent instructions run `refresh` after ref changes and search the actual files/diff separately for in-flight edits; this **does not** solve uncommitted search. Tradeoffs: transient embedding cost, races as files change, ignore/security policy, and avoiding accidental retention or network disclosure of uncommitted content. Test staged-versus-unstaged divergence, untracked/deleted files, detached HEAD, branch switch, stale indexed HEAD, concurrent writes, and clean-tree default parity; report false-negative rate for current-task questions.

### P0 — indexed snapshots are not change-intent or relationship retrieval

**Verified.** [`src/history.rs::prepare_refresh`](../../src/history.rs) stores commit ID, committer timestamp, blob/path occurrence and indexed-unit ranges; [`publish_refresh`](../../src/history.rs) creates no commit-message, parent-edge, patch, rename, or issue/PR-link table. `search` returns a selected occurrence and unit rather than a change. [`src/main.rs::SearchResult`](../../src/main.rs) has source reference fields but no rationale, parent, or issue-link fields. [`docs/agents/issue-tracker.md`](../agents/issue-tracker.md) puts issues/specs in GitHub Issues, not RepoDB's searchable corpus. The source-context brief proposes complete changes and direct dependencies but reports no cost/quality benchmark ([`docs/issue-36-source-context-research.md`](../issue-36-source-context-research.md)). **Impact (inference):** agents can find where a construct existed, but cannot ask RepoDB why it changed, identify a deletion absent from the selected tree, or follow a result to the motivating issue. A raw code mention of `#32` is not a verified issue relationship.

**Proposal.** Index a separate change entity keyed by immutable commit and parent IDs, with commit message, bounded searchable diff summary, old/new paths and line mappings, and typed links to issues/PRs/ADRs with link provenance. Keep full patch retrievable on demand rather than assuming all patch bytes belong in embeddings. Merge commits need an explicit parent-selection policy; rename detection is heuristic and should record confidence, not assert identity. Acquire issue bodies/comments only with explicit network/permission policy and pinned provenance. Evaluate answerability on curated “why was this changed?”, deletion, rename, regression, and issue-to-code tasks against Git log/diff plus manually verified issue links; separately measure bytes, refresh latency and relevance. This is a proposal, not implemented functionality.

### P1 — duplicate collapse sacrifices chronology and path context

**Verified.** [`src/history.rs::search`](../../src/history.rs) partitions eligible occurrences by `blob_id`, then selects one with `ORDER BY timestamp DESC, o.commit_id DESC, path ASC`; filtering occurs first. The chosen occurrence's segmentation kind selects its units. The [`README.md`, “References, duplicates, and ordering”](../../README.md) warns this is committer-time policy, **not ancestry ordering**, and identical unit text in distinct blobs is not collapsed. **Impact (inference):** an all-history answer may attribute old text to a later copy, a timestamp-skewed commit, or another path; a file moved or represented as both docs/source may return only one path and one segmentation. A single-commit scope is an effective existing workaround, while all-history is not an occurrence timeline.

**Proposal.** Preserve current compact default but expose `--occurrences`/`--timeline` with all source references and parent-aware chronology per branch; offer path-constrained searching **before** collapse, with a clear default for multi-path identity. Do not claim a total ancestry order for unrelated branches. Add fixtures for timestamp skew, divergent branches, rename/copy, same blob with `.md` and `.rs`, exclusion revealing a different occurrence, repeated unit text in different blobs, and answer attribution. More occurrences increase tokens and may crowd ranking; attach occurrence lists to one indexed unit unless explicitly expanded.

### P1 — local/imported scope and provenance have asymmetric semantics

**Verified.** [`src/main.rs::SearchScope::matches`](../../src/main.rs) implements `source`, `repo-local-source`, `repo-local-docs`, `all-docs`, and `all` using inferred path type and whether `repo_id` is present. In `execute`, local `scope.resolve` selects commits and `history::search` receives them, but [`src/imports.rs::search`](../../src/imports.rs) receives no eligible-commit set: imported results are appended for all three modes regardless of `--commit`/`--exclude-commit`. This is consistent with local commit selectors applying to *repository-local history*, but easy to misunderstand as a corpus-wide temporal filter. An imported Git result has `repo_id` and commit ID; standalone document versions instead place a byte hash in `blob_id` ([`src/imports.rs::search`](../../src/imports.rs)). [`src/imports/sources.rs::register`](../../src/imports/sources.rs) pins a Git revision when registered; re-registering resolves it anew, whereas a subsequent full refresh uses the stored pin. Remote Git registration can clone/fetch **during `import`**, even though searching never fetches. `import --preview` handles local files/directories only and is not an import of the listed directory. [`tests/cli.rs::git_import_accepts_one_optional_revision_and_pins_it_to_the_resolved_commit`, `import_preview_reports_selected_files_sizes_and_exclusions_without_db_side_effects`, `search_scope_filters_repo_and_document_sources_for_all_modes`](../../tests/cli.rs) exercise important portions of this behavior.

**Impact (inference).** An agent asking for a precise historical local commit may also get newer or unrelated imported hits. `source` includes imported Git source but not standalone `.rs` imports; classification by extension can omit unsupported/ambiguous code. A repository-local-only search can avoid cross-origin noise, but misses dependency knowledge. **Proposal.** Add explicit `--origin local|imports|all`, repeatable imported-source IDs, and an imported revision/version selector; make JSON field names distinguish `git_blob_id` from document `source_version_hash`, expose `requested_revision` and `pinned_commit` in result metadata, and make network activity explicit on import/refresh. `--revision` already exists for *registration* of a Git import; it does not select revisions at search time. Keep local-only as default for automated acquisition, while existing search default may remain `all` for compatibility. Add conflicting-selector checks, mixed local/imported fixture with identical text, and stable source-reference validation. A breaking change to default scope needs migration guidance.

### P1 — retrieval quality and scale remain unproven for agent tasks

**Verified.** [`src/segmentation.rs::kind`, `visit`, `bounded`](../../src/segmentation.rs) assign syntax/paragraph/fallback segmentation by case-sensitive extension, cap indexed units at 4096 UTF-8 bytes, and fall back to blank-line paragraphs on parser failure. [`README.md`, “Indexed units and source ranges”](../../README.md) notes exact queries spanning indexed units cannot match, and binary/invalid UTF-8 blobs have no searchable units. [`src/main.rs::execute`](../../src/main.rs) defaults embedding candidate limit to 20; combined mode retains all exact hits plus semantic candidates. [`src/history.rs::search`](../../src/history.rs) builds and sorts local candidate rows; exact/combined hydrate text while scanning candidate units. [`src/imports.rs::search`](../../src/imports.rs) scans imported units, calculating semantic distances row by row; imported Git exact/combined hydrates before deciding matches. `src/imports.rs::refresh` embeds each imported Git unit and visits each imported source sequentially; local history instead batches and reuses repeated blob/kind units (`src/history.rs::prepare_refresh`). **Inference:** uncommon file types, cross-boundary questions, lexical synonym gaps, fallback partitions, mixed origins, large corpus scans and repeated imports can degrade either recall, latency, or token efficiency; this is not a measured ranking-quality claim.

**Measured but narrow:** [`docs/issue-32-benchmark.md`](../issue-32-benchmark.md) compares historical builds on 96 reachable commits, 14,924 local units and 7,060 imported Git units using a deterministic 2-D stub vector. In that fixture the updated blob-backed build's warm exact-common query was 0.070 s vs 0.030 s baseline, combined-common 0.110 s vs 0.055 s, and primary DB size 6,250,496 vs 25,284,608 bytes. These are **not** current-tree numbers, cold-cache results, real-model throughput, or agent-quality evidence; the document explicitly says so. [`docs/issue-36-source-context-research.md`](../issue-36-source-context-research.md) proposes growth warnings but has no source-specific storage measurements. [`src/imports/sources.rs::preview`](../../src/imports/sources.rs) currently returns `estimated_net_db_growth_bytes: null`, uses raw source bytes as warning basis (50,000,000 bytes or >2× existing DB), and does not actually estimate deduplicated growth.

**Proposal.** Build a pinned multi-repository task suite with source-location, edit-navigation, change-rationale, dependency and docs questions; score recall@k, answer/source-reference correctness, path diversity, end-to-end latency, peak RSS, embedding invocations, refresh time and bytes by origin/model. Stratify by language, file size, history depth, duplicate rates, and index freshness; compare exact, embedding, combined, origin-scoped, and candidate reranking at fixed token budgets. Explore FTS/inverted candidate filtering and indexed embedding top-k only after profiling, since a candidate index can improve speed while hurting recall; make document/code segmentation and source gaps measurable. Assess net-growth previews using dedup-aware estimates with `unknown` until measured. Do not set quality or scale thresholds from the issue #32 stub fixture.

### P1 — environment/setup and agent integration require explicit contract

**Verified.** [`src/config.rs::embedding_command`, `semgrep_core`](../../src/config.rs) default to `~/bin/generate_embeddings` with `all-MiniLM-L6-v2` and config/env lookup; [`src/segmentation.rs::visit`, `semgrep_core_is_pinned`](../../src/segmentation.rs) require Semgrep core v1.181.0 for recognized source during refresh even when an external segmenter is configured. [`README.md`, “Imported sources” and “Indexed units”](../../README.md) requires `pdftotext` to convert PDF imports. [`src/main.rs::execute`](../../src/main.rs) exposes CLI commands and JSON output, but no index-inspection/status/doctor command in this command dispatch; `search` itself does not refresh. [`skills/repodb-enabler/SKILL.md`](../../skills/repodb-enabler/SKILL.md) requires the agent to check executable and database availability, discourages automatic refresh and ordinary-task searches, and says availability is not proof of freshness or semantic readiness. [`skills/repodb-help/SKILL.md`](../../skills/repodb-help/SKILL.md) says scoped search options are not provided by its described interface, although the CLI's `--scope` and history selectors are documented in the README. These guidance files therefore do not give an agent a complete, current decision procedure for scope or freshness. [`tests/cli.rs::run_with_env`](../../tests/cli.rs) supplies a controlled Semgrep core and stub embedder in tests, so passing such tests would not demonstrate out-of-box availability on agent hosts. README calls integration unfinished and alpha software. `AGENTS.md` documents only a small search/refresh recipe; the issue-tracker and domain-doc agent conventions live in [`docs/agents/`](../agents/), outside RepoDB search orchestration.

**Impact (inference).** A fresh agent host may fail indexing before its first useful answer; a zero-result search may mean no match, unsupported content, stale scope, or empty snapshot. Subprocess embedding commands may involve different privacy/cost properties depending on user configuration; this code does not establish that a chosen command is local-only. **Proposal.** Add `repodb doctor`/`status --json` with tool availability/version, schema, indexed and live HEAD, indexed-unit counts by reason/type, imports' pins/fetch state, model ID and freshness. Supply a small machine-readable agent workflow that checks status, selects origin and scope, handles errors, and labels source references; avoid auto-refresh on every search. Document tool trust/privacy and optional hook status without installing/enabling anything. Test pristine hosts, missing/wrong Semgrep, missing embedder/Poppler, unsupported/binary files, permission failures and CLI JSON error codes; distinguish dependency failure from a genuinely empty answer.

### P2 — additional correctness/UX caveats

- **Document conversion:** [`src/imports.rs::html_text`](../../src/imports.rs) strips tags/scripts/styles with a simple scanner and decodes a short list of entities; HTML headings, tables, URLs and links do not become structured source references. **Hypothesis:** some documents lose useful context. Compare extraction with golden HTML/PDF fixtures and page/section verification before adding another converter; different conversion versions may change indexed text.
- **Output volume and references:** [`src/main.rs::execute`](../../src/main.rs) prints every exact match and full indexed-unit text, and combined keeps every exact match even with `--semantic-limit`. **Inference:** common literals can flood an agent's context; offer pagination, exact-result caps with explicit `truncated` metadata, compact previews and on-demand full indexed-unit retrieval. Test deterministic ordering and whether capped results hide needed source references.
- **Nomenclature:** `--current-worktree` actually denotes checked-out HEAD ([`README.md`](../../README.md); [`GLOSSARY.md`](../../GLOSSARY.md)). Rename only with compatibility aliases; do not silently change its reproducible meaning when introducing an overlay.

## Prioritization and evaluation gates

| Order | Smallest useful increment | Release gate / tradeoff |
| --- | --- | --- |
| P0 | `status --json` with live/index HEAD and machine-readable stale/empty reason; document existing HEAD-only semantics | Test no DB, changed HEAD, deleted refs, dirty checkout. Status exposes a problem without solving it. |
| P0 | Opt-in ephemeral uncommitted overlay, then change metadata/diff retrieval | End-to-end edit/review and “why changed?” task accuracy; snapshot provenance and privacy review. Overlay and change indexing increase computation/storage complexity. |
| P1 | Origin/import selectors, explicit version/pin metadata, occurrence/timeline mode | Mixed-origin and chronological attribution fixtures; stable legacy defaults. More control increases CLI complexity. |
| P1 | Retrieval/scale benchmark and instrumentation, then candidate optimization | Reproducible task-quality + latency/RSS/bytes results, real embedder and cold/warm distinction. Avoid premature indexing/ranking changes. |
| P2 | Better document conversion, pagination, skill/agent recipe | Golden source-reference tests and token-budget measurements; migration and tool availability documentation. |

## Contradictions and missing evidence

- The README's phrase “all commit selectors and filters apply equally to exact, semantic, and combined search” describes *modes* correctly for local history, but does not mean imported results are filtered by the selected local commit. `src/main.rs::execute` and `src/imports.rs::search` show this distinction; clarify it in UX/docs.
- [`docs/issue-36-source-context-research.md`](../issue-36-source-context-research.md) recommends growth estimation and co-primary change/dependency sources; current `src/imports/sources.rs::preview` reports unknown estimated growth, and `src/history.rs` does not index change entities. This is an aspirational design versus implementation gap, not conflicting measurements.
- Git status, skill inventory, and three targeted tests were checked by the parent after the researcher's restricted run. There are still no current-code benchmarks, task-relevance scores, dependency-license audit, or externally validated documentation. No claim of a specific issue's motivation or a particular uncommitted edit is made. The issue #32 historical timing cannot establish performance on larger repositories or current code. No Git-object dependence is counted as a weakness.
