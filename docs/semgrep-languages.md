# Semgrep language routing

Semgrep's source inventory is pinned to v1.181.0 `cli/src/semgrep/semgrep_interfaces/Language.ml`. Its 46 dedicated parser constructors include proprietary Apex, Elixir, and Gosu. The 43 OSS candidates are Bash, C, Cairo, Circom, Clojure, C++, C#, Dart, Dockerfile, FGA, Go, Hack, HTML, Java, JavaScript, JSON, Jsonnet, Julia, Kotlin, Lisp, Lua, Move on Sui, Move on Aptos, OCaml, PHP, PowerShell, PromQL, Protobuf, Python 2, Python 3, Python, R, Ruby, Rust, Scala, Scheme, Solidity, Swift, Terraform, TypeScript, Vue, XML, and YAML.

## Runtime scope and probe evidence

The v1.181.0 bundled core produced AST output for valid minimal fixtures for all 41 OSS dedicated parsers other than PowerShell and Vue. PowerShell fails with `Parsing_plugin.Missing_plugin`; Vue reports support removed. Empty files are not used as parser-availability evidence. The probe included valid FGA, JSON, Jsonnet, PromQL, Protobuf, and Cairo fixtures; Cairo's valid fixture was `fn main() {}` (a guessed legacy `func` fixture fails).

YAML has a narrow structural exception: in v1.181.0 generic AST, `Container` nodes have opening/closing delimiter slots that can contain synthetic `OriginTok` punctuation. Only those two structurally identified slots are skipped for YAML, whether or not their token text matches source. The `Container` shape and delimiter markers must be well-formed. Every token outside those slots remains subject to exact UTF-8 byte/text validation, and all source gaps are retained in the final complete partition. Unexpected container shape or any outside-slot mismatch rejects the whole AST and falls back. Fake-AST tests prove both matching and mismatching delimiter-slot markers are skipped, but a mismatching token outside a delimiter slot is rejected.

Manual real-core RepoDB validation covered YAML mappings, block and flow sequences, quoted parentheses, Unicode in comments, comments around mappings, and multiple `---` documents. The multi-document fixture produces one meaningful unit spanning both documents and their separator, rather than separate document units. In flow collections, punctuation omitted by Semgrep's delimiter slots can appear in a neighboring gap unit; complete source bytes remain indexed. A Unicode scalar token that Semgrep serializes with text differing from source is rejected by the ordinary token check and falls back; Unicode in comments/gaps is retained while the surrounding YAML syntax unit is accepted.

`src/semgrep_languages.rs` records the pinned 41-parser runtime inventory and conservative extension routing. Semgrep is the source-code parser interface, including Rust; RepoDB does not use a separate `syn` parser. Python 2/3 suffixes `.py2`/`.py3` map specifically, while `.py` maps to generic Python. `.move` maps to an internal `move` target that runs both `move_on_sui` and `move_on_aptos`: it accepts exactly one valid result or identical complete partitions, and falls back on disagreement. The real v1.181.0 probe `module 0x2::sample { public fun hello(): u64 { 1 } }` yields different spans (`[7,48)` vs `[9,50)`), so RepoDB deliberately falls back for that ambiguous dialect. `.h` remains fallback because C/C++ collide. Hack's `.hack` suffix is routed, while `.php` remains mapped to PHP. Dockerfile (no extension) and `.dockerfile` map to its parser. Other extensions not listed remain on the heuristic fallback.

## Required source runtime

Semgrep core v1.181.0 is required whenever refresh encounters a source kind with a dedicated parser. Configure its executable under `[tools].semgrep_core` in `$XDG_CONFIG_HOME/repodb/config.toml`, defaulting to `~/.config/repodb/config.toml` when `XDG_CONFIG_HOME` is unset. `REPODB_SEMGREP_CORE`, when set, overrides the file value. A missing or wrong-version runtime fails refresh; it is not silently replaced with paragraph chunks. RepoDB verifies `-version`, writes each exact UTF-8 source to an exclusive mode-0600 temporary file, and invokes `-l <canonical-language> -json -full_token_info -dump_ast <file>`. The optional range segmenter can be set as `[tools].segmenter` or overridden by `REPODB_SEGMENTER`; it still requires the Semgrep runtime to be configured and validated first.

For a successful AST, RepoDB validates token positions/text, computes each top-level `Pr` child's span, adds every gap (comments, whitespace, separators, and omitted delimiter punctuation) into a full partition, and sends it through the same ordered/bounds/UTF-8 validator and line-range handler used by the generic segmenter. Parser rejection, timeout, nonzero exit, oversized or malformed output, invalid token, overlap, or incomplete AST falls back heuristically for that source; only a missing or wrong-version runtime is fatal. Unit tests use constructed AST values for token-validation edge cases; no fake Semgrep-core executable is used. The `.github/workflows/semgrep-core.yml` job provisions the pinned official Semgrep distribution, which bundles the upstream core, then runs the corpus and Go adapter tests. Ordinary `cargo test` also requires the runtime and fails rather than skipping parser checks. Locally, provision Semgrep 1.181.0 first, then set `REPODB_SEMGREP_CORE` or `[tools].semgrep_core` to its bundled `semgrep-core` path. The integration gate itself makes no network requests.
