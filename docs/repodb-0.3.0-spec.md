# RepoDB 0.3.0 — implementation spec

Status: **approved; tracked in [GitHub issue #57](https://github.com/emfrom/repodb/issues/57)**. Source: [agent-workflow research](research/agentic-workflow-weaknesses.md), [source-context research](issue-36-source-context-research.md), and open issues [#54](https://github.com/emfrom/repodb/issues/54) and [#55](https://github.com/emfrom/repodb/issues/55). Research claims about external sources and real-model performance have not been independently validated. These are requirements for 0.3.0, not descriptions of current behavior. The research proposals were reviewed individually; the decisions below supersede proposals where they differ.

## Outcome and boundaries

An agent can search a selected committed view, its changes and rationale, and optionally the active staged/worktree changes; distinguish what was actually indexed, what was mapped forward, and what was never semantically searched; and inspect references without overflowing its context. A website import is a reproducible, bounded collection of extracted text versions from a **single URL**. Native tracked history and explicitly added external Git repositories are Git content, not size-gated document imports.

- No plaintext from tracked Git files, historical diffs, or commit messages is persisted in the current schema. Keep range/anchor references and embeddings; hydrate text from Git objects for search and presentation. This requirement does not apply to website snapshots: their extracted text is retained for offline search/display. Existing legacy-schema migration must preserve search semantics.
- No staged or worktree embeddings or persistent staged/worktree diff index. Do not fetch or refresh on search except for best-effort local inspection of the active worktree when requested. A configured embedding command's trust/privacy properties must be disclosed; never send uncommitted text to it.
- Do not resolve GitHub issues/PRs or ingest their bodies/comments in this release. A textual issue number is not an authenticated relationship. External Git-object availability remains an intentional dependency; missing objects produce explicit errors, not silently fabricated results.
- [#55](https://github.com/emfrom/repodb/issues/55), bounded link crawling, is **deferred**: neither importing one URL nor following HTTP redirects traverses page links. Retain the ticket as possible later work; do not mark it implemented by 0.3.0. [#54](https://github.com/emfrom/repodb/issues/54) is in scope.

## Committed history and changes

1. Full refresh records complete tracked trees for every captured commit, including unchanged files, as today; continue to reuse blob/segmentation units. Record immutable commit-parent edges (including every merge parent), but do not persist mutable branch labels. A result for a specific commit can identify the file present there even when that commit did not edit it. Ref membership can be resolved from Git when needed. Deleted refs and missing objects must obey explicit refresh/search behavior rather than being silently reinterpreted.
2. Index commit-message units for exact and embedding search. Store commit ID and bounded message byte/line ranges, not message plaintext; hydrate from the commit object. Index historical diff plaintext on **both added and removed sides** for exact and embedding search, without storing that plaintext. Each bounded diff unit has a hunk identity, side, parent and child commit IDs, old/new path and line anchors, and byte/range information sufficient to reconstruct and display its text from Git. For a whole-file addition/deletion the absent endpoint is null; for other edits both endpoints have real anchors. Root commits compare to the empty tree. Compare merges independently against **each** parent. Diff results make parent choice visible. Segment changed text into bounded units using the existing indexed-unit approach where applicable; test cross-unit search limitations explicitly.
3. Record rename/copy classification, old/new paths, and detection settings/confidence as heuristic metadata, not as guaranteed file identity. Given a diff result, expose shell-safe complete `git show <parent>:<old-path>` / `git show <child>:<new-path>` commands for each existing side to dump the involved files; do not dump whole files in search results. Handle unusual Git path bytes without command injection or misleading shell syntax. Changed text remains retrievable from available Git objects; never substitute a different object if one is missing.
4. Ordinary search collapses duplicate blob occurrences to a compact result but warns in human output when multiple eligible historical references were collapsed: use `--explore` to inspect them. Machine-readable output records the collapse/count where known. `--explore` enumerates **all eligible references across pages**, not an unbounded single response. No new general path-constrained search filter or separate occurrence/timeline mode is required.

### One history interface

`--history=off|all|<file-or-directory>|n`, with bare `--history` equivalent to `all`; default is `off`. `off` selects checked-out HEAD's file content, message, and parent diffs, plus staged/worktree augmentation only if enabled. `all` searches every captured commit on indexed refs. `n` selects the first n commits in deterministic topological traversal reachable from the start commit, including merged ancestry, not timestamp order. A file/directory argument searches that path's content and changes in commits reachable from the start commit, including directory descendants; follow detected renames by default and label heuristic links, showing the path at each commit. It does not select unrelated files merely because they occurred in the same commit. `--commit=ID` changes the starting commit for history traversal as if that commit were HEAD. `--include-commit` adds exact commits, `--exclude-commit` removes them (exclusion wins); report invalid/missing commits. Existing `--all-history` remains a compatibility alias with documented conflicts/migration. Preserve existing unambiguous selector behavior where possible. Imported-source commit selection remains separate: local `--commit` does not filter external imports; document this prominently and defer imported-revision/origin selectors.

## Active checkout augmentation

`--worktree` is opt-in, only with the actual checked-out HEAD as start commit and only when that HEAD is captured in the index. An alternate `--commit` plus `--worktree` fails, as does a stale/missing indexed HEAD; report a machine-readable reason and refresh guidance. The existing `--current-worktree` name continues to mean HEAD-only; never silently change its meaning. HEAD → staged and staged → live worktree are distinct layers; eligible untracked files appear as additions. Discover untracked files as ordinary `git status` would, respecting ignore rules; unsupported/binary/excluded files appear in coverage metadata. No on-disk retained overlay. Best-effort inspection on each search may observe concurrent changes; label time and state/coverage, without claiming an atomic snapshot.

- **Exact:** augment the committed view using added/changed lines (including eligible untracked text) and remove no-longer-live matches; return matches in the live view, not duplicated/deleted HEAD matches. Preserve HEAD/staged/live provenance and the relevant matched HEAD lines where they exist, bounded by the common response budget. Permit on-demand Git inspection of old text. Implementation may use Git status plus grep or derive transient diffs; do not mandate a persistent index. Staged and worktree text never gets an embedding.
- **Semantic:** rank indexed HEAD units using their existing embeddings, map matched HEAD line ranges through the staged and live diffs, and present **live text** at the mapped range. Label the semantic distance `similarity to indexed HEAD text`, mark changed live text, and report the original matched HEAD lines (not the full old unit) and provenance. If a range was deleted or mapping is ambiguous, retain the HEAD reference and mark mapping deleted/ambiguous; never guess a live location. Flag newly staged/untracked content with no semantic coverage and report other excluded coverage. Do not insert literal diff hits into the semantic result list or claim the mapped text was embedded.
- JSON results and human output distinguish origin/state, indexed HEAD, actual HEAD, mapping status, mode/ranking, snapshot observation and coverage. An embedding distance is a similarity/ranking signal, **not** a calibrated probability of a correct answer. Search/`--explore` can never silently present a stale mapped range as current.

## Search interface, ranking and output

The same filters and ranking apply to `search` and `search --explore`; explore returns **references only**, not text. `--type=all|content|cmdiffs|diffs|cmcommits|commits` chooses respectively: all three; file content + diffs; commit messages + diffs; diffs only; commit messages + file content; commit messages only. Default `all`. A small set of coarse choices may be configured rather than making agents manage internal result classes. Clearly label each returned component and its matching side; avoid hidden scope changes. Imported results remain distinguishable by origin and version; current local commit selectors do not filter imports.

- In combined mode, guarantee one exact and one semantic-only slot when both exist; exact matches also receive semantic scores and are ranked within the available semantic evidence. Give remaining slots to the best scores across categories. A missing category yields its slots to the other. In exact-only mode, use semantic ranking if available, otherwise deterministic non-semantic ordering; report the method in metadata without treating fallback as semantic coverage. Semantic-only mode uses measured embedding distance. Specify stable tie breaks by source identity, commit, parent, path, side, and range; no timestamp-as-ancestry claims.
- With `--type=all`, group overlapping file/diff evidence instead of consuming two slots for one changed passage, and ensure a slot for distinct diff evidence if present. **Diff is primary** in such a group. A commit-message match lifts its commit's change as one grouped result with the matched message and references to parent diffs (including every merge parent); expand diffs on demand rather than spending every slot on one commit. Rank grouped changes using the best message/diff semantic score and name the component that supplied it. The group counts toward exact or semantic-only allocation according to its best matching component. No separate reserved message slot. If no diff exists, retain the message hit with its commit reference rather than losing it. Evaluate ranking and group fairness in the pinned task suite; document any measured adjustments before release.
- Default normal search: at most **5 complete results** and provisionally **5 KB total serialized response**. Explore: **50 references** and the same provisional 5 KB. Both configurable. Count *everything* emitted, including references, HEAD matches, live text, metadata, help, warnings, and pagination fields. Paginate deterministically with a stable cursor/snapshot identity, `truncated` and total count when cheaply available; report unknown otherwise. Never cut result text mid-result. If a complete result cannot fit, emit its reference with a `text_omitted_for_size` flag and a way to fetch it separately; if even minimal metadata cannot fit, return an explicit limit error, not an empty page or broken cursor. Explore can enumerate every eligible historical reference over successive pages. Evaluate and finalize the provisional 5 KB limit against task relevance and token cost.

## Website snapshots and import safety (#54; #55 deferred)

A URL fetch imports **only that URL's resulting page**. Follow HTTP redirects by default (including cross-origin), with a finite configurable redirect bound. Record requested and final URL, redirect chain and retrieval times; redirects do not authorize crawling links. A website is fetched again only by an explicit website refresh; ordinary search and general repository refresh never fetch it. Search works offline from retained extracted searchable text, not raw HTML or rendered layout. Improve HTML extraction so headings, links/targets and tables retain useful context; fixed HTML/PDF fixtures must test text and accurate page/section references. Improve PDF conversion only for verified defects.

The explicitly requested URL is the source identity, even if multiple sources redirect to the same destination; deduplicate identical extracted text internally. Hash the **extracted indexed text** for content-version identity and distinguish it from a fetch identity (requested URL + retrieval time); also retain the final URL. For an unchanged re-fetch update first/latest successful retrieval timestamps without duplicating searchable text or logging an unbounded series of identical events. Default retention is newest distinct version only. Opt-in per-source history retains at most 2 distinct versions by default, configurable; prune oldest excess versions and report what was pruned. Retained versions' extracted text and provenance must remain searchable offline; raw response bytes need not be kept. An HTTP failure, unsupported response, or failed conversion leaves the last successful snapshot searchable with a stale/failed-fetch indicator and clear status/type; never replace it with an error page.

For websites and local documents, fetch/read into a temporary file, evaluate the import warning threshold, then apply `--size-limit=error|warn|ignore`, default `error`: `error` rejects an over-threshold import, `warn` reports the breach and **continues**, `ignore` continues without warning. Use existing thresholds: estimated net DB growth ≥50 MB **or** >2× existing DB size; when net growth is unknown, use measured source bytes as the fallback basis and label it as such. Provide a dedup-aware estimate where feasible, otherwise explicitly `unknown`; report both source size and estimated growth, never claim source bytes are net growth. Clean up temporary files on all outcomes. This is a post-fetch gate, not a download-byte cap or an interactive approval prompt. A separate maximum download size may be considered later. No size gate applies to native Git history or explicitly added Git repositories: tracking their selected commits is part of the Git contract, and Git object bytes are not copied as document imports. Other policy-required approvals remain separate from `--size-limit`.

## Status, integration and release verification

`status --json` (or `doctor --json` with an equally stable contract) reports database/schema state, indexed and live HEAD, clean/dirty and staged/untracked coverage, stale/empty reasons, indexed searchable counts by type and unsupported reason, imports' pins and fetch/version status, configured model identity, and readiness **per capability** (exact, semantic, refresh, document conversion/import). Missing optional dependencies do not block unaffected operations. JSON errors distinguish missing DB, missing tool, stale HEAD, unsupported content, missing Git object, invalid scope and genuinely empty results. Document local vs imported commit-selector semantics, no automatic network fetch, provenance, privacy of configurable subprocesses, and the optional post-commit hook; never install/enable hooks automatically. Refresh after ref changes is explicit. Provide small, task-specific agent skills with short routing pointers for status, history/explore, importing and augmented search; no sprawling omnibus skill. Skills describe actual CLI behavior and when to inspect the filesystem or Git instead of inferring from zero matches.

Release tests use isolated Git repos and local HTTP fixtures. Cover unchanged files in commits, branch divergence/timestamp skew, every merge parent, initial commits, changed/removed/added lines, rename/copy confidence, unusual paths, missing/pruned Git objects, stale HEAD, staged-versus-live divergence, untracked/ignored/binary/deleted files, concurrent worktree edits, semantic live mapping/score labeling, filters/grouping/ranking and deterministic capped pagination, website redirects/failures/unchanged fetches/dedup/pruning/offline retrieval, `--size-limit` modes, HTML/PDF references and dependency failures. Full CLI integration tests assert exact and semantic provenance and no tracked plaintext persisted; static skill tests assert consistency.

Build a pinned, multi-repository agent-task suite (source location, edit navigation, rationale, deletion/rename/regression, docs and dependency questions) with verified source references. Compare baseline versus 0.3.0 at fixed response budgets: recall@k, answer/source-reference accuracy, coverage false negatives, path diversity, end-to-end latency, cold/warm behavior, peak RSS, embedding calls, refresh time and bytes by origin/model; stratify by language, size, history depth, duplicates and freshness. Include a real embedding model; the historical 2-D stub benchmark is not a quality or scale threshold. No regression in existing exact-search correctness. Publish reproducible measurements and tradeoffs; establish numeric quality/performance thresholds from the measured baseline **before release**, then gate the release on them. Profile before adding FTS/inverted or vector candidate indexes; optimize only as necessary to satisfy measured thresholds without degrading recall. External API/rights claims from preliminary research require primary-source verification before they become release assertions.
