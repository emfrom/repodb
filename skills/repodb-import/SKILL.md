# RepoDB import

Use this skill only when RepoDB is available for the current repository. Availability requires both an executable `repodb` command and an initialized database; do not initialize a database as part of this skill. If either is unavailable, explain what is missing and stop.

Register exactly one source per call: one HTTP(S) URL, one local file, or one Git repository. A supplied HTTP(S) URL selects exactly that page; it never crawls links or follows site navigation. Local directory preview is supported, but registration imports one file at a time. Do not combine source types or multiple sources in one call.

## Local documentation preview and import

The following preview steps apply to local files and directories. `repodb import --preview` also accepts one HTTP(S) page URL through the separate URL-preview flow below; Git repositories are not previewed.

1. Check applicable repository instructions, including `AGENTS.md`, for import/approval policy. Do not infer an approval requirement if none is stated.
2. Run `repodb import --preview PATH` for the selected local file or directory. Preview is read-only. No imports have been performed until the preview has been shown and the policy decision to proceed has been made.
3. Parse the JSON preview and use it as the sole source of truth for scope and support. Do not independently walk, filter, or reinterpret the path. Respect all preview boundaries, including excluded symlinks and `.git` directories; never traverse outside the selected scope.
4. Before any import, show the complete preview: every entry in `selected_supported_local_files` and every entry in `unsupported_regular_files` with its reason. Report `total_selected_source_bytes`, `current_db_bytes`, `estimated_net_db_growth_bytes` (including null/unknown), `warning_basis_bytes`, and `warn_large`, using the CLI-reported byte units. These totals describe all preview-selected supported files, including preview-supported formats outside this skill's scope; do not present them as an exact size estimate for the documentation files you will import. Unsupported files are excluded from imports. Where useful, offer alternatives such as converting to a supported format or selecting a supported file explicitly.
5. If `warn_large` is true, clearly flag the large-import warning and show `warning_basis_bytes` plus available source, database, and growth sizes. The CLI's warning thresholds are at least 50 MB (50,000,000 bytes) or estimated net growth greater than twice the current database size; when growth is unknown, the warning basis falls back to total selected source bytes. This preview warning does not itself import or select a size policy. When proceeding, the later import refresh defaults to `--size-limit=error`; use `refresh --imports --size-limit=warn` to continue with a warning or `--size-limit=ignore` to continue silently. Apply any approval required by repository policy; otherwise the agent may decide whether to proceed. Ask the user only for an approval policy requirement or a genuine user-owned decision.
6. If policy requires approval, obtain it before proceeding. If proceeding is approved by policy or the agent's decision where no approval is required, make that decision explicit. If not proceeding, stop without importing or refreshing.

## URL preview and import

1. Check applicable policy before network access. If policy requires approval for a URL request, obtain it before previewing.
2. Run `repodb import --preview URL` for the one explicitly selected HTTP(S) page. This performs one GET using the single-page import's HTTP(S)-only redirect policy and timeout. It follows no links, registers no source, writes no database content, and does not update retrieval timestamps. It has no fixed source-byte ceiling.
3. Show `selected_url`, `total_selected_source_bytes`, `current_db_bytes`, `estimated_net_db_growth_bytes` (including null/unknown), `warning_basis_bytes`, and `warn_large`. URL growth cannot currently be estimated, so `estimated_net_db_growth_bytes` is null and the warning basis is response-body source bytes. Flag `warn_large` at 50,000,000 source bytes or when source bytes exceed twice the current database size. A size warning alone does not require user approval; apply any approval required by repository policy.
4. If proceeding, run `repodb import URL` with the same selected URL. This registers the URL without fetching; only the later refresh fetches and may observe different bytes than the preview. It imports only that page. Do not crawl links or follow site navigation. Then follow the refresh/report workflow below.

## Git repository import

A Git repository is one source per invocation. Use `repodb import [--revision REV] REPOSITORY`; default is `HEAD`. `repodb import REPOSITORY` selects HEAD, or `repodb import --revision REV REPOSITORY` selects one branch, tag, or commit. The `--revision` option precedes the repository argument. RepoDB resolves the selected revision to a resolved commit SHA and pins the imported snapshot to that commit; report the SHA as its version/provenance. Do not import full history. A later refresh must continue using the resolved commit for that source, even if a branch or tag moves. Do not combine a Git repository with another source in one invocation.

## Local documentation import scope

A local import registers one explicitly selected file. `import --preview` may inspect a file or directory; for a directory, use its selected-file list and register supported files individually. Supported documentation formats are Markdown, plain-text, PDF, HTML, or Org formats, plus extensionless files: Markdown (`.md`, `.markdown`), plain text (`.txt`), PDF, HTML, and Org mode (`.org`). The CLI supports `.rs` files for backward compatibility, but source-code files are outside this documentation skill's scope. Use the preview as the source of truth for enumeration and CLI support; when it lists `.rs`, report it as preview-supported but out of skill scope and do not import it. Never expand selection to a parent, sibling, workspace, or another directory.

## Import, refresh, and report

For local documentation, after the complete preview and proceed decision, import only selected paths returned by the preview that are within this skill's documentation scope. Invoke `repodb import FILE` separately once for each in-scope path; never pass a batch or directory as an import, and never invoke imports for unsupported or out-of-scope paths. For URL sources, use the URL preview/import flow above. Git sources are not previewed.

After successful local/URL import registration, run one explicit `repodb refresh --imports` to fetch/read and index the registered sources without refreshing repository history. This applies `--size-limit=error|warn|ignore` (default `error`) to local/URL documents: an over-threshold import errors without publishing, `warn` reports source bytes and estimated growth or its labeled source-byte fallback and continues, and `ignore` continues without a warning. Git repository registration and refresh are not subject to this document size gate. Do not initialize or refresh before imports, and do not imply that an import succeeded when its command failed. Report which imports succeeded or failed, whether import refresh succeeded, and only the source provenance the CLI actually provides. For a URL, the URL is the source locator. JSON search results expose the imported version as `blob_id`, which is the SHA-256 of fetched response-body bytes, plus `first_retrieved_at` and `last_retrieved_at` in UTC RFC3339 (`Z`) format. Legacy snapshots whose first observation time is unknown keep `first_retrieved_at` null even after a later refresh; that refresh updates `last_retrieved_at` without inventing historical provenance. Search is offline and never fetches; only explicit full or `refresh --imports` refresh observes registered URLs. `repodb retention latest` keeps the most recently successfully published version (including A→B→A returning A as latest); if a pruned hash returns, its `first_retrieved_at` starts a new retained-row lifetime because discarded metadata cannot be reconstructed. `all` keeps distinct hashes, deduplicates unchanged bytes, and preserves their first timestamps. The default remains `latest`. Local preview file lists and unsupported-format fields apply only to local selections. If an import, preview, or import refresh fails, report the error honestly and any resulting partial completion.
