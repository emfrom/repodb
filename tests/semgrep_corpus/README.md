# Semgrep source corpus (#27)

The final language list, ranking caveats, parser IDs and extensions are recorded in [issue #28](https://github.com/emfrom/repodb/issues/28): 24 usable entries from the 2026 Stack Overflow Developer Survey “used” chart, plus unranked Move. HTML covers only HTML from the combined HTML/CSS survey entry; Bash does not imply all shells. Python 2/3 count as one language. Move's Sui and Aptos parsers count as two dialects of the same 25th language. There are **26 small fixtures**: one per survey-selected language and one for each Move dialect.

`generate_fixtures.py` regenerates the checked-in `sources/*/sample.*` files. They are independent idiomatic syntax examples, not equivalent programs. Each has one unique `Repodb…SampleV1` marker; tests change it to `V2` at a second Git commit. No common registry, audit behavior, or arbitrary line-count target is required.

`corpus_tests.rs` runs one isolated end-to-end CLI test per fixture: a fresh Git repository and **fresh, explicit `--database` SQLite file**, real Semgrep Core v1.181.0 AST validation, `repodb init`, exact search with commit/path/line references, and a comparison of indexed byte ranges with Semgrep's validated syntax spans. The two Move parser results are reconciled by RepoDB: if both disagree, a paragraph fallback is expected and checked rather than reported as syntactic success. One additional all-language test indexes all 26 fixtures at V1, commits V2, refreshes, then searches both versions for every fixture. The deterministic fake embedder used by the CLI test helper avoids network access; Semgrep Core itself is never faked.

The pinned real core is required in ordinary tests and in `scripts/test-semgrep-core.sh` / CI. Set `REPODB_SEMGREP_CORE` or use the installed Semgrep distribution's bundled core. The test suite does not install software or make network requests.
