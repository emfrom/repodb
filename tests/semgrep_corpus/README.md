# Semgrep language corpus (provisional)

This corpus is a provisional 25-language candidate set for issue #27; the final language/ranking decision and shared program semantics are pending in issue #28. It currently contains 50 checked-in source files (two per language), each 200–229 lines. The fixtures sketch the same small in-memory entity registry, audit-event type, and create/find/archive API. The primary entity name has a `V1` suffix so the history integration test can rename it to `V2` in a second commit.

The language list is intentionally a candidate, not a claim that these are objectively the top 25 by a particular popularity ranking. It is drawn from the Semgrep v1.181.0 OSS parser set. Move is represented as one high-level language using both Sui and Aptos parser alternatives; Rust uses RepoDB's built-in `syn` path.

`generate_fixtures.py` deterministically regenerates `sources/<language>/registry_{alpha,beta}.<extension>`. Each non-Rust fixture test invokes the real Semgrep core v1.181.0 and verifies its AST and every `OriginTok` byte position against the source; Rust fixture tests exercise RepoDB's built-in parser. The history test refreshes V1 with the real core when available, changes all 50 entity names to V2 in a second commit, refreshes with the optional core unavailable, and checks both versions' reachable commit/path/line references. If Semgrep is unavailable, the history test still runs using fallback segmentation. A deterministic fake embedder is used for CLI indexing; no fake Semgrep core is used. Real-core parser tests skip with a diagnostic if Semgrep core v1.181.0 is unavailable; set `REPODB_SEMGREP_CORE` to its executable path to select it explicitly. Tests do not use network access.
